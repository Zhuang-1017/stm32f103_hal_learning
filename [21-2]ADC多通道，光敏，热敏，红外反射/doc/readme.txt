【一】三个通道与引脚
================================================================
  ADC1_IN4  <-  PA4   标签 Lignt_AO（CubeMX 里把 Light 拼错了，不影响功能）
  ADC1_IN5  <-  PA5   标签 Ir_AO    红外反射
  ADC1_IN6  <-  PA6   标签 Hot_AO   热敏

  ADCCLK = PCLK2 / 6 = 72 / 6 = 12 MHz（F103 上限 14 MHz，留了余量）
  12 位分辨率、右对齐、单次转换、软件触发
  换算： voltage = adc * 3.3 / 4095        （0 -> 0 V，4095 -> 3.3 V）

  对照 21-1：那边是单通道（IN6），这边是三个通道，多出来的全部复杂度
  都在「怎么让序列指针自己往前走」这一件事上。

================================================================
【二】核心认知：为什么 for 循环里重复 HAL_ADC_Start 能采到不同通道
================================================================
CubeMX 里的三个勾选项决定了这件事，缺一不可：

  ScanConvMode          = ENABLE     使能扫描序列
  NbrOfConversion       = 3          序列里有 3 个 rank（CH4/CH5/CH6）
  DiscontinuousConvMode = ENABLE     ★ 关键：间断转换模式
  NbrOfDiscConversion   = 1          每次触发只转 1 个通道

  两种配置的区别：
  ----------------------------------------------------------------
  DISCEN = DISABLE（连续扫描）
    一次 Start 把整个序列 3 个通道全转完，EOC 只在序列末尾置位一次。
    循环里再 Start 会「重新从 rank1 开始」-> 三次读到的全是 CH4，
    另外两路永远是同一个数，而且看起来还挺稳定，极难发现。
  ----------------------------------------------------------------
  DISCEN = ENABLE + Num = 1（本工程）
    每次 Start 只转 1 个通道，EOC 每个通道置位一次，序列指针自动前进。
    第 1 次 Start -> CH4，第 2 次 -> CH5，第 3 次 -> CH6，
    第 4 次回绕到 CH4。这才是 for 循环三次能拿到三路的原因。
  ----------------------------------------------------------------

  底层：HAL_ADC_Init 里把 DISCEN 和 DISCONTINUOUS_NUM 一起写进 ADC_CR1。

  另一个容易担心的点：循环里反复 Start 合法吗？
  合法。HAL_ADC_PollForConversion 在返回 HAL_OK 之前会
      CLEAR_BIT(hadc->State, HAL_ADC_STATE_REG_BUSY);
      SET_BIT (hadc->State, HAL_ADC_STATE_READY);
  状态已经回到 READY，下一次 Start 不会返 HAL_BUSY。
  如果换成中断方式（Start_IT），就必须等转换完成回调里再 Start，
  否则第二次 Start 会因为 BUSY 直接返回、静默丢一次采集。

================================================================
【三】换算公式：一个已修掉的致命写法
================================================================
  原写法（错）：
      voltage[i] = adc_val[i] / 4095 * 3.3f;
  adc_val 是 uint32_t，4095 是 int，两个整数先相除 —— 结果只能是 0 或 1，
  再乘 3.3 就变成 0.000 或 3.300。实测只有 adc 恰好 4095 时才得 1。
  表现：三行全部打印 0.000，很容易误判成接线错或传感器坏。

  现在（对）：
      voltage[i] = (float)adc_val[i] / 4095 * 3.3f;

  等价写法： adc_val[i] * 3.3f / 4095      （先乘浮点，不会截断）
  关键规律： 只要表达式里有一个 float，整条式子就按浮点算；
             全是整数时除法会被截断，而且编译器不会给任何警告。

【四】必须知道：采样时间 1.5 cycles 太短（尚未修改）
================================================================
  当前三个通道都是 ADC_SAMPLETIME_1CYCLE_5，@12 MHz 只有 125 ns。
  ST 手册的判据：  Ts >= (Radc + Rain) * (n+2) * ln2 * C
  n = 12、C ≈ 8 pF、Radc ≈ 1 kΩ => 每 1 Ω 源阻抗需要约 78 ps 采样时间。

  换算出来的容限：
      1.5   cycles (125 ns)  ->  允许源阻抗仅   610 Ω
      7.5   cycles (625 ns)  ->                  7.0 kΩ
      13.5  cycles (1.13 us) ->                 13.5 kΩ
      55.5  cycles (4.63 us) ->                 58.6 kΩ   ★ 推荐
      239.5 cycles (20 us)   ->                  256 kΩ

  影响（按充电未满 exp(-Ts/((Radc+Rain)*C)) 估算，读数系统性偏低）：
      源阻抗  5 kΩ  -> 偏低约  7 %
      源阻抗 10 kΩ  -> 偏低约 24 %
      源阻抗 47 kΩ  -> 偏低约 72 %

  光敏/热敏这类模块的 AO 脚多由分压或运放输出，等效源阻抗常在几 kΩ 到
  几十 kΩ，1.5 cycles 明显不够。而且不同通道偏低的比例不一样，
  看起来像「三个传感器精度不一致」，实际是采样时间不够。

  改法：CubeMX -> Analog -> ADC1 -> Parameter Settings ->
        Rank 1/2/3 的 Sampling Time 全改成 55.5 Cycles，重新生成。
  代价：单通道转换时间从 14 周期变成 68 周期（1.17 us -> 5.7 us），
        三路合计约 17 us，对 500 ms 的循环周期完全无影响。

  先实测再决定：接已知电压（比如 3.3 V 分压得到 1.65 V）看读数是 2048
  还是明显偏低，偏低就是这个问题。

【五】三个坑
================================================================
  ① 引脚和以前的模块冲突，做实验前必须拔掉
     PA4  [11]/[12] 的按键模块 K1
     PA5  [18] 的外部中断按键 KEY_EXTI0
     PA6  [12] 的蜂鸣器 beef
     切到 GPIO_MODE_ANALOG 后，这些引脚的内部上下拉会被关闭。
     按键模块不按时是悬空 -> 读数乱跳；按下时被拉到 0 V 或 3.3 V 满量程；
     蜂鸣器模块的输出脚挂在线路上同样会把电压带偏。
     现象：读数忽大忽小、和传感器状态无关 —— 先查这个，不要怀疑 ADC。

  ② 传感器模块必须是 4 针带 AO 的那种
     W2 用过的三针光敏模块只有 DO（比较器数字输出），接 ADC 读到的
     只有 0 和 4095 两个值，永远采不到中间量。要 AO 版本。

  ③ printf 用 %.3f 需要勾 Use MicroLIB
     本工程已勾（useUlib=1）。没勾的话 printf 会走 semihosting，
     程序一进 main 就卡死：灯不亮、串口无输出、调试器暂停停在 _sys_exit。

【六】验收
================================================================
  串口 115200 8N1，每 500 ms 一行：
      光敏（IN4）： 1.650 V,反射（IN5）：0.820 V，热敏（IN6）：2.310 V

  判据（用万用表量 PA4/PA5/PA6 的实际电压对照，差 0.05 V 内算正常）：
      遮住光敏        -> IN4 电压明显上升（分压型模块）
      白纸靠近反射管  -> IN5 电压变化（反射强 -> 接收管导通增加）
      手指捏住热敏    -> IN6 电压朝一个方向缓慢变化（热惯性，要等十几秒）

  三路读数都不动、且都接近 0 或都接近 3.3 -> 先查引脚冲突（坑①）。
  三路读数都在动但比例都偏小 -> 采样时间不够（第四节）。
  三路读数完全相同 -> 大概率 DISCEN 没开（第二节）。

【七】已知的健壮性弱点（不影响本次验收）
================================================================
  · 没有检查 HAL_ADC_PollForConversion 的返回值。超时（50 ms）时
    if 不成立，adc_val[i] / voltage[i] 保留上一次的旧值，串口照样打印，
    看不出异常。严格做法是 else 分支里置错误标志或打印一次告警。
  · 数组是 .bss 里的全局变量，上电初值为 0，所以第一次若超时会打印 0.000。
  · CubeMX 标签拼写错误：Lignt_AO（应为 Light_AO）。只影响可读性。

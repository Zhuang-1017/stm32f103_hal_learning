================ 以上为原始笔记，以下是补充 ================

【硬件：手上没有电位器怎么办】
这个实验真正需要的只是一个"能变的电压"，电位器只是最方便的来源。

方案一 · 两只固定电阻分压（最稳）
  3.3V --[R1 10k]--●--[R2 10k]-- GND，取样点 ● 接 PA6
  等值电阻时取样点 1.65 V，期望读数 ≈ 2048。
  换比例可得不同电压：R1=10k/R2=4.7k -> 1.06 V(≈1315)；R1=4.7k/R2=10k -> 2.25 V(≈2790)；
  R1 短接 -> 0 V(0)；R2 短接 -> 3.3 V(4095)。
  三个点（0 / 1.65 / 3.3）就能验证线性度，比"连续可调"更能说明问题。
  为什么用 10k 不用 100Ω 或 1M：太小静态电流大，太大采样电容充不满（见坑①）。

方案二 · 直接接 3.3V 或 GND（30 秒验证）
  PA6 接 3.3V -> 4095；接 GND -> 0。
  只有两个端点，不能演示变化，但能一次性确认通道号、时钟、引脚模式、换算公式都对。

方案三 · 手指 / 铅笔石墨（能看到连续变化，只能定性）
  两根杜邦线，一根 3.3V、一根 PA6，手指同时捏住裸金属，人体电阻几百 kΩ~MΩ，读数随力度变。
  更像样的做法：纸上用 2B 铅笔涂一条 3cm 长、5mm 宽的粗线（石墨有电阻），两端接 3.3V 和 GND，
  第三根线在线条上滑动取分压 —— 这就是一个"纸上的滑动变阻器"。
  注意源阻抗是 MΩ 级，采样时间必须调到 239.5 cycles，否则读数偏低且乱跳。

方案四 · 光敏模块如果有 AO 脚
  3 针（VCC/GND/DO）只有比较器输出，不能接 ADC；4 针多一个 AO 就能直接接 PA6，
  遮光/照光即可看到连续变化，还能复用 W2 的硬件。

【CubeMX 配置】
- ADC1 -> IN6（PA6），Rank 1
- ScanConvMode = Disable（单通道不用扫描）
- ContinuousConvMode = Disable（单次转换，每次软件启动）
- ExternalTrigConv = Software Start，DataAlign = Right，NbrOfConversion = 1
- ADCCLK = PCLK2 / 6 = 12 MHz（F103 上限 14 MHz，不能再往上分）

【采样流程（阻塞轮询）】
  上电：HAL_ADCEx_Calibration_Start(&hadc1) 一次
  while(1)：HAL_ADC_Start -> HAL_ADC_PollForConversion(50) -> HAL_ADC_GetValue
            -> voltage = adc_val / 4095 * 3.3f -> printf -> HAL_Delay(500)
  单次转换模式下每轮都要重新 Start；PollForConversion 成功后 HAL 会把 state 置回 READY，
  所以在循环里重复 Start 是合法的，不需要额外 Stop。

【换算公式的两个版本】
  除以 4095：把满量程映射到 3.3 V，4095 -> 3.300 V，绝大多数例程这么写，本工程也是
  除以 4096：按码字间隔算，更接近理论值（12 位 ADC 有 4096 个码）
  两者差 1 LSB ≈ 0.806 mV，工程上可忽略。被追问时就答"差一个 LSB，除 4095 是让满量程落在 3.3 V"。

【三个坑】
① 采样时间 1.5 cycles 太短（当前工程就是 1.5，建议改成 55.5 或 239.5）
   ADC 采样本质是给内部采样电容（约 8 pF）充电，充电时间常数 = 源阻抗 x C。
   ST 的判据：Ts >= (n+2) x ln2 x Rain x C，n = 12 时约 78 ps x Rain。
   Ts = 1.5 cycles @12 MHz = 125 ns，只允许源阻抗 1.6 kΩ 左右（还要扣掉内部约 1 kΩ 的开关电阻）。
   两只 10 k 分压的等效源阻抗是 5 kΩ，**明显超了**，读数会系统性偏低 5%~10%，
   而且换个分压比例误差就变 —— 很容易误判成"接线或公式错了"。
   改法：55.5 cycles（4.6 us，允许约 58 kΩ）够用；手指/石墨这类 MΩ 级源必须 239.5（20 us）。

② PA6 同时是蜂鸣器引脚（[12] 按键触发蜂鸣器用的就是它）
   蜂鸣器模块还插着的话会分走电流、把读数拉低。做 ADC 实验前先拔掉。

③ 校准只能在上电后调一次
   HAL_ADCEx_Calibration_Start 不能放进 while 循环（会不断打断转换）。
   很多例程漏掉这一步，读数会整体偏移几十个 LSB。

【验收（串口助手 115200 8N1）】
  接 GND      -> ADC ≈ 0     , 电压 ≈ 0.000 V
  接 3.3V     -> ADC ≈ 4095  , 电压 ≈ 3.300 V
  10k+10k 分压 -> ADC ≈ 2048 , 电压 ≈ 1.650 V（允许 ±30 个 LSB 的偏差）
  手捏两根线   -> 数值随力度变化（只能定性看）

【中文显示为什么改了写法】
  原 main.c 是 GBK 编码，编译进 Flash 的中文字面量就是 GBK 字节，野火助手按 GBK 解码正好正常。
  但这个仓库统一用 UTF-8 with BOM（这样 GitHub 和 Keil 里中文注释都不乱），
  转码之后字面量会变成 UTF-8 字节 -> 串口助手就成了乱码。
  处理办法：源文件转 UTF-8 with BOM，同时把 printf 里的中文预先转成 GBK 字节，
  用 \xNN 转义写死（见 main.c 第 114 行）。源文件可读、烧进芯片的仍是 GBK。
  注意 "\xNN" 后面紧跟十六进制字符时要用 "" 断开，否则转义会把后面的字符吞掉。
